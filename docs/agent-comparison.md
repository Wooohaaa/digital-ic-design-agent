# 开源 agent 对照与第二轮优化

查阅日期：2026-11-05。对照对象为 OpenCode、Hermes Agent，以及 Command Code 官方公开文档和仓库。本轮未核实 Command Code 的完整运行时源码，因此涉及它的比较仅依据公开说明。下面的改动是 IC Forge 的独立实现。

| 官方资料中的机制 | IC Forge 上一轮的缺口 | 本轮已实现 |
|---|---|---|
| [OpenCode 技能](https://opencode.ai/docs/skills/)通过元数据发现、按需加载 SKILL.md，并兼容多个技能目录 | 没有技能目录，跨 agent 的流程知识不能直接复用 | 兼容 `.agents`、`.opencode`、`.claude`、`.commandcode`、`.hermes` 以及原生 `.icforge`；显示来源和同名冲突；按需加载正文与引用资源 |
| [OpenCode 配置](https://opencode.ai/docs/config/#compaction)提供上下文压缩和保留空间设置 | 固定截取源码和最近历史，缺少整体输入预算 | 按 JSON 字符数限制输入、保留空间、分阶段裁剪可重读数据，并记录各部分用量；保护目标、追加要求及加载中的技能 |
| [Hermes 持久记忆](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)将跨会话记忆限制在有界空间；[技能系统](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)按需披露流程知识 | 工作记忆仅属于当前任务，较早的结果不容易检索 | 检索历史任务目标与工作记忆、按任务ID和步数找回归档；返回来源并标记历史性质，验收仍依据当前工程证据 |
| [Command Code 上下文文档](https://commandcode.ai/docs/context)提供用量分解、分层压缩和原始日志保留；[技能文档](https://commandcode.ai/docs/skills)说明多来源发现 | 用户看不到规划上下文的占用，也没有细粒度读取工具 | `/context`、输入预算报告、原始上下文快照和步骤日志；新增 inspect/search/skill/recall/unload-skill 五个受限工具 |

## 具体解决的问题

1. **源码尾部不可见。** 之前自动上下文仅包含每份源码前 12,000 字符。现在给出原文件指纹、片段长度和截断标记，planner 可以按行继续读取。大文件只提供索引，避免组装上下文本身占用大量内存。
2. **压缩后无法追溯。** 裁剪只改变本次模型输入；被裁剪上下文保存在该步 `context-full.json`，工具输出另有每步日志。历史步骤可通过引用分页找回。
3. **长会话盲目溢出。** 默认 96,000 字符的本地预算预留 8,000 字符空间。明确的服务端上下文溢出会触发有界缩减重试；核心内容超过预算时明确阻塞，允许恢复时扩大预算。
4. **流程知识无法迁移。** 现有技能可直接被发现，无需复制其他 agent 的配置或凭据。正文按需加载；内容发生变化会标记过期。
5. **历史成功被误当成当前成功。** recall 的每条结果带任务来源和 `historical_only` 标记。当前指纹、验证、实现和交付门槛继续由宿主检查。
6. **会话交接丢失已讨论的规格。** 转入持续任务时，同时保留最新请求与会话整理出的设计 brief；交接失败时拒绝执行，避免误回退成旧的单次计划。

## 本轮边界与后续优先级

本轮的预算依据字符数，尚未接入每个模型的 tokenizer 或真实 API usage；历史检索是有界关键词检索，不是向量记忆。技能是文本流程知识，不能自动执行附带脚本。日志保留有上限，达到上限会标记截断，最新输出尾部仍保留。

后续优先补：实际 token/费用计量、长时间远端 API 稳定性回归、工程变更快照与回退，以及有来源和失效规则的工程事实记忆。持续任务跨天稳定性、自动学习用户偏好和自动生成可靠技能仍需单独验证。

功能用法和限制见 [技能、历史经验与上下文](knowledge-context.md)。
