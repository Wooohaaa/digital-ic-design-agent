# 党哥的 RSI Chip 路线图

日期：2026-11-17。状态：已采纳的项目方向与分阶段验收计划，未完成能力不作实现声明。
需求来源：用户给定的七阶段目标。基础实现：[IC Forge](https://github.com/Wooohaaa/digital-ic-design-agent)，
本次起点 `fa8368a37202cf38ab9211f99edc9b6dfb2f39d3`。
公开项目入口：[RSI-Labs/RSI-Chip](https://github.com/rsi-labs/rsi-chip)。

## 总目标与执行方式

由 AI Agent 主导需求拆解、EDA 开发、芯片设计、验证、实验分析与迭代，最终使 Agent、EDA、模型和计算硬件形成可量化的共同改进闭环。
人提供方向及现实资源边界。执行记录须标明使用的模型、工具、输入、预算和人工干预；人工提供的签核、PDK、设备、生产或物理操作如实记录。
Agent 生成设计，验证方持有独立规格、参考模型、测试与门禁；设计修复不能自行修改验收标准。

每个候选版本都保留：需求 → 实现 → 仿真/形式证据 → 综合/物理证据 → 指标 → 接受或回退。
只有在独立验收和固定预算下得到可重复改进，才计作进化；一次生成成功、自测 PASS 或增加代码量不计作闭环成立。

## 七阶段验收

| 阶段 | 目标和主要产物 | 进入下一阶段的证据 |
| --- | --- | --- |
| 1：Agent-driven EDA | SV 前端与 elaboration、事件/四态仿真、明确的最小 UVM 契约、综合、网表、严格 LEC、统一 Agent API 与可回放证据 | 固定规范版本和支持矩阵；正向/拒绝/差分测试；UVM 最小子集逐项运行；组合及时序 LEC 的正反例；RTL→网表可复现；在已声明范围对照商用工具的正确性与质量 |
| 2：RV32I CPU | Agent 自主生成和修复最小 CPU、独立 ISA 模型、定向/随机程序、benchmark、退休事件比对、可复现综合产物 | ISA/EEI 契约冻结；官方架构测试与另一独立实现交叉核验；指令/异常/访存覆盖闭合；变异测试证明检查器能找错；CPU 时序 LEC；不将有限测试解释成无条件正确性证明 |
| 3：RVA23 商用 CPU | 分步完成 64 位应用处理器 profile、微架构、存储体系、SoC、软件栈、DFT 与 ASIC 实现 | 固定 profile/扩展/特权规范；一致性和系统验证；量化性能/面积/能耗目标；完整 signoff 清单与报告；工艺/封装/测试就绪后 tapeout，回来后完成硅后验收 |
| 4：tiny GPU | 极小 PTX 子集、解释器、编译/运行时、SIMT 执行与存储模型；仅推理的最小 GPU | PTX 版本/指令/类型/地址空间和执行语义白名单；不支持项显式拒绝；kernel 差分、数值容差和访存检查；矩阵运算及小模型推理端到端复现 |
| 5：推理 LPU | 在明确模型与负载下探索全新推理架构，完成编译器、runtime、权重/激活/KV 数据流与内存方案 | 开源模型的许可、checkpoint 和精度契约固定；prefill/decode、吞吐、尾延迟、能耗和质量同口径比较；模型能运行在实现的硬件上；改进形成可测的初步闭环 |
| 6：数据中心训练与推理 | 可扩展训练 GPU 和推理 LPU；互连、通信栈、编排、RAS；Agent 利用模型训练结果推进下一代芯片 | 训练收敛与质量可复现；通信/同步/故障恢复验证；从单机到集群的效率和能耗曲线；记录模型更新→EDA/芯片改进→新训练收益的因果链与资源账本 |
| 7：全计算体系重构 | CPU/SoC 的 IO、协议、通信、编解码，以及不同功耗/场景的训练 GPU、推理 LPU 联合探索 | 按实际场景分配计算/存储/通信预算；跨层一致性与系统级验证；多代可复现 Pareto 改进；硬件收益回到 Agent 的模型与设计能力评估 |

阶段可开展局部交叉试验：现有 RV32I 是 Stage 1 的回归负载，不需要等“所有 SV 功能完成”才使用；阶段退出条件仍需逐条满足。
“初步达到 Cadence/Synopsys 能力”是长期对照目标。必须选定产品、流程范围、版本、设计集合和 PPA/正确性指标后比较，不能用接入第三方综合器来宣称已实现自研全栈 EDA。

## 需要冻结的技术契约

1. **SV / UVM**：v0.14 机器契约（SV 目标 1800-2023、UVM 1800.2-2020/官方 2020.3.1）包含 29 个用例和 38 个有界特性。外部工具通过仅说明约定范围内的行为，见 [有界 SV/UVM 契约](uvm-profile.md)。
2. **LEC**：组合证明、状态对应、复位/初态、存储器、X 语义、黑盒和技术库分别声明。任何假设进入证据，timeout、unsupported 和 unproven 均不能通过。当前三核 core LEC 按声明的初态/复位后契约通过，完整 SoC、多时钟、重定时与物理库仍待扩展，见 [LEC 边界](lec.md)。
3. **RV32I / RVA23**：现有 RV32I 核采用仓库自定义测试 EEI，不是完整特权平台。RVA23 是 profile 家族，包含 RVA23U64/RVA23S64；Stage 3 暂以 S64 应用处理器为候选，最终扩展和平台范围待冻结。参见 [官方 RVA23 profile](https://docs.riscv.org/reference/rva23/v1.0/rva23-profiles.html)。
4. **PTX / CUDA**：先交付“选定 PTX 子集 kernel 可执行”的精确兼容边界；CUDA 源码、runtime/driver API、库和二进制兼容分别验收。PTX 子集执行不直接意味着 CUDA 软件生态兼容。依据 [NVIDIA PTX ISA 文档](https://docs.nvidia.com/cuda/parallel-thread-execution/)。
5. **LPU**：此处指项目自己的推理专用处理器方向，尚未选定现有厂商架构。首个模型、上下文长度、精度、batch、功耗和内存容量均待基于实测选定。
6. **商业与流片**：必须落实目标工艺、标准单元/存储宏、PDK、约束、STA、CDC/RDC、DFT、功耗/电源完整性、DRC/LVS/ERC、封装及硅后测试。FPGA route、正 WNS、网表 LEC 均不能替代这些项目。

## 首轮执行与近期顺序

- **M0 基线**：保留来源 commit，核查代码与上游报告，复测软件和三种 RV32I 核；见 [本轮基线](rsi-baseline-2026-11-17.md)。
- **M1 组合综合/LEC**：已加入 `icforge lec` 与 Agent typed action、输入和产物指纹、必选门禁、归档复核；穷举加法器验证和组合 SAT 正例、错误网表反例可复现。它是对现有外部工具的集成。
- **M2 时序证明**：基础范围已闭合。状态双射与显式复位后状态关系均核验完整状态、基例、全部迁移/输出和异步复位事件。单周期/两级流水 RV32I 核分别通过 1,128/1,193 位状态的强契约；多周期核以复位后契约证明 1,338→1,336 位合并状态，且真实工程均启用必选 core LEC。多时钟、重定时/重编码、工艺库及完整 SoC 仍待扩展，不能据此关闭 Stage 1/2。见 [时序契约](lec-state.md) 与 [复位后契约](lec-reset.md)。
- **M3 SV/UVM 契约**：v0.14 在同源 FIFO 流程中交叉比较占用量、读写请求和复位优先级，并保留 v0.13 的竞争复位覆盖。全语言、最小 UVM 语义完备和自研后端仍是后续验收目标。Rust RSI-Chip 未导入或验证。
- **FIFO 独立规格证明**：[两槽 FIFO](fifo-spec-proof.md)在首次同步复位后的任意二值输入序列满足占用、顺序和复位优先规则；和 M2 的网表等价分别报告。
- **可复用规格验收**：[公共规格入口](spec-acceptance.md)通过两槽 FIFO 和 8 位计数器，统一生成同步复位基例、关系保持、端口性质及可达反例，并支持本地重验证据。
- **工程规格门禁**：四槽 `sync_fifo` 的仿真、LEC 和规格分别验收。复位错误的 RTL 可通过原仿真和对自身网表的 LEC，但规格 SAT 反例会阻止交付；通过的 ZIP 可在解包后复核。
- **分层工程复验**：现有 8 位计数器经顶层包装接入同一门禁。两份有序 RTL、顶层参数默认值与独立参考纳入证据，从 ZIP 恢复可再次验收。
- **带等待状态的外设**：APB 寄存器工程通过仿真、网表 LEC 和独立规格门禁。验证范围涵盖单周期等待、背靠背请求、复位取消、错误响应和写入只提交一次，见[规格验收](spec-acceptance.md)。
- **M4 CPU 独立验证基线**：三种 RV32I 核接入 Unicorn 外部参考，按退休、内存写入和最终 RAM 比对，并通过 ACT 2.7.4 的 38 个 RV32I 用例。见 [RV32I 外部参考](rv32-external-reference.md)与 [ACT 签名](rv32-act.md)。
- **Stage 2 本地验收**：冻结 RV32I 2.1 终止型 EEI，并统一重放模型产物、覆盖、异常、ACT、时序 LEC 和网表验证。约束及复现方式见 [Stage 2 验收](rv32-stage2.md)。
- **Stage 3 M1 整数执行**：以 RVA23S64 1.0 为阶段目标，先交付 RV64I 2.1 的 30 条整型计算指令、小端单 hart 执行核、Unicorn 退休差分和严格网表 LEC。范围及验收见 [RV64I 整数执行里程碑](rva23-m1-integer.md)。
- **Stage 3 工程基线**：扩展至 RV64I 控制流和访存、机器态同步陷阱与返回、LLVM 裸机 C、50 项上游 RV64I 签名、独立 Sv39/Svade 遍历器和 ECP5 核级布局布线。当前覆盖、复现和完整阶段的剩余门槛见 [Stage 3 验收](rva23-stage3.md)。

下一步是把现有 RV64I、机器态和页表遍历器集成到可启动软件的系统，继续补齐 RVA23S64 扩展并扩大 Stage 1 的 SV/UVM 语义范围。Stage 4–7 保留各自的退出条件。商用性能目标和完工日期取决于平台、工艺、资源与验证要求。

## RSI 实验记录要求

每轮固定 workload、验证器版本、模型版本/输入、搜索预算和硬件/工具环境；保留基线与候选、失败原因、质量/性能/资源变化及干预次数。
留出从未用于候选修复的评估集。接受候选前重跑必要回归，改动验证器则单独审阅并重建证据，不沿用旧分数。
